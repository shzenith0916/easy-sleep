# 코골이 구간 추출 — 설계 기록

규칙기반으로 코골이 구간을 잘라 학습데이터를 만드는 프로젝트의 설계 결정과 스크립트 핵심 정리.

---

## 1. 프로젝트 목표

모바일로 녹음한 코골이 오디오에서 **코골이 구간만 잘라낸 클립 파일**을 생성한다. 이 클립들은 이후 코골이 검출 모델의 **학습데이터**로 사용한다.

- 검출 방식: 규칙기반 (학습 모델 아님, 바로 동작)
- 출력 형태: 구간별로 잘린 여러 개의 클립 파일
- 우선순위: **정밀도(precision) > 재현율(recall)**
  - 학습 라벨이 깨끗해야 하므로, 애매한 구간은 버리더라도 잘린 클립은 확실히 코골이여야 한다.

---

## 2. 핵심 설계 결정 — "파일 종류로 분기하지 않는다"

### 처음 가졌던 고민
업로드 파일의 특성이 제각각이다:
- 6~8시간짜리 긴 파일 (옆에 두고 자서 노이즈 심함)
- 이미 코골이 구간만 잘려 있는 파일
- 15분 단위로 쪼개진 파일

"파일 종류에 따라 전처리를 분기해야 하지 않나? 이게 학습 전처리 == 추론 전처리 동일성 원칙과도 맥락이 같다"고 생각했다.

### 옳았던 부분
- 일률적인 절대 임계값(예: "특정 dB 이상")으로 자르면 안 된다는 직관은 정확. 노이즈 많은 긴 파일과 정제된 클립에 같은 절대값을 쓰면 한쪽은 오검출, 한쪽은 과삭제.
- **학습 전처리 == 추론 전처리** 동일성 원칙도 정확. train/inference skew는 반드시 피해야 한다.

### 어긋났던 부분
"파일 종류"를 기준으로 **전처리 파이프라인을 분기**하려 한 것이 함정이었다:

1. **분기 자체가 train/inference skew를 만든다.** 추론 때 들어온 파일이 어느 분기인지 항상 정확히 판정된다는 보장이 없다. 분기 분류가 틀리면 학습 때와 다른 전처리를 거치게 되어, 지키려던 원칙이 깨진다.
2. **파일 길이는 검출과 무관한 변수다.** 결국 검출은 "짧은 윈도우 단위로 코골이냐 아니냐"로 환원된다. 길이는 윈도우 개수 차이일 뿐, 윈도우 하나를 처리하는 로직은 같아야 한다.
3. **노이즈 차이는 "파일 종류"가 아니라 "그 파일의 노이즈 플로어"의 문제다.** 긴 파일이 시끄러운 건 길어서가 아니라 환경 노이즈가 높아서다. 이건 **적응형 기준**으로 흡수할 변수지 분기할 변수가 아니다.

### 결론: 분기 대신 정규화
분기점을 "파일 종류"가 아니라 **"파일 내부 통계"**로 옮긴다. 모든 파일에 **동일한 단일 파이프라인**을 적용하되, 임계값을 파일별 통계에서 적응적으로 뽑는다.

→ "이미 잘린 파일"은 거의 전 구간이 코골이로 잡혀 통과하고, 긴 파일은 자기 baseline 기준으로 알아서 추려진다. **분기가 사라지니 train/inference 전처리가 자동으로 동일**해진다.

## 3. 검출 로직 — 세 신호의 AND 결합

음량만 보면 단발 소음(문 닫는 소리, 차 소리)에 속는다. 그래서 세 신호를 **모두 만족(AND)**해야 코골이로 인정한다.

| 신호            | 내용                                               | 거르는 대상 |
| --------------- | -------------------------------------------------- | ----------- |
| ① 적응형 에너지 | 파일별 노이즈 플로어(하위 백분위) 대비 충분히 큰가 | 조용한 배경 |
| ② 저주파 비중   | 에너지가 코골이 대역(80~600Hz)에 몰려 있는가       | 고주파 소음 |
| ③ 호흡 주기성   | 검출이 규칙적 간격(약 2~6초)으로 반복되는가        | 단발성 소음 |

핵심은 ③ **주기성**이다. 코골이는 호흡 주기마다 끊겼다 이어지는 반복 패턴이고, 이 반복성이 일회성 소음과 코골이를 가르는 결정적 단서다.

---

## 4. 처리 파이프라인

1. **고정 윈도우 슬라이싱** — 길이 무관, 전부 1초 프레임 + 0.5초 hop(50% overlap)으로 쪼갬.
2. **파일별 노이즈 플로어 추정** — 에너지 하위 백분위를 그 파일의 baseline으로. 절대 dB 아닌 상대 기준 → 적응형.
3. **밴드패스 + 주기성** — 저주파 비중과 호흡 간격 반복을 함께 검사.
4. **윈도우 판정 → 에피소드 병합** — 연속/근접 검출을 하나의 코골이 에피소드로 묶고, 너무 짧은 건 버림.

> 참고: 위 **1초/0.5초는 검출용 분석 프레임**(`FRAME_SEC`/`HOP_SEC`)이다. 이 스크립트의 출력은 1초 클립이 아니라 **에피소드(≥5초)**이고, 모델이 먹는 **클립 길이(`CLIP_SEC`, 기본 4초)는 별개**로 다운스트림 `episode_to_clips`(utils/clip_features.py)에서 정해진다. 즉 *검출 프레임(A)* 과 *모델 입력 클립(B)* 은 서로 다른 층이다. (9장 문서 참고)

## 5. 디버깅에서 배운 것 (튜닝 시 주의)

테스트 중 검출은 완벽한데 클립이 0개 나온 문제가 있었다. 원인:

- **병합 간격이 호흡 주기보다 짧으면 안 된다.** 처음 `MERGE_GAP_SEC=2.0`초로 두었더니, 호흡 사이 4초 침묵을 못 메워 코골이 하나하나가 개별 세그먼트로 쪼개졌다. 그러면 세그먼트당 이벤트가 1개뿐이라 주기성 판단이 불가능해져 전부 탈락.
- 주기성은 "여러 호흡이 모인 한 에피소드" 안에서 봐야 한다. → 병합 간격을 호흡 주기보다 넉넉하게(`8.0`초) 키워 개별 호흡을 하나의 에피소드로 묶도록 수정.

**교훈:** `MERGE_GAP_SEC`(병합 간격)는 반드시 호흡 주기보다 커야 하고, `MIN_SEG_SEC`(최소 길이)·`PERIODICITY_MIN_EVENTS`(최소 반복 횟수)와 함께 조율해야 한다.

## 6. 스크립트 주요 설정값

모두 코드 상단에 모여 있어 조정 가능. 대부분 적응형이라 건드릴 일은 적다.

| 변수                     | 기본값     | 의미                                                           |
| ------------------------ | ---------- | -------------------------------------------------------------- |
| `SR`                     | 16000      | 분석용 샘플레이트 통일 (코골이는 고주파 불필요)                |
| `FRAME_SEC` / `HOP_SEC`  | 1.0 / 0.5  | 분석 윈도우 길이 / 이동 간격                                   |
| `SNORE_BAND`             | (80, 600)  | 코골이 핵심 주파수 대역 (Hz)                                   |
| `MERGE_GAP_SEC`          | 8.0        | 이 간격 이내 검출은 한 에피소드로 병합 (호흡 주기보다 커야 함) |
| `MIN_SEG_SEC`            | 5.0        | 이보다 짧은 에피소드는 버림                                    |
| `PAD_SEC`                | 0.3        | 클립 앞뒤 여유                                                 |
| `PERIODICITY_MIN_EVENTS` | 3          | 한 에피소드 내 최소 반복 이벤트 수                             |
| `PERIOD_RANGE_SEC`       | (1.5, 7.0) | 정상 코골이 호흡 간격 범위                                     |

### 민감도 프리셋
| 프리셋       | 성격                           | floor_pct / energy_mult / lowband_min |
| ------------ | ------------------------------ | ------------------------------------- |
| `high`(기본) | 정밀도 우선, 확실한 것만       | 30 / 4.0 / 0.55                       |
| `medium`     | 균형                           | 25 / 3.0 / 0.45                       |
| `low`        | 재현율 우선, 많이 잡되 노이즈↑ | 20 / 2.2 / 0.35                       |

## 7. 사용법

```bash
pip install librosa soundfile numpy scipy

# 한 파일
python snore_extract.py night.wav

# 여러 파일 일괄
python snore_extract.py ./recordings/*.m4a -o ./clips

# 검출만 확인 (파일 미생성) + 타임스탬프 CSV
python snore_extract.py night.wav --dry-run --csv check.csv
```

- 민감도: `-s high`(기본) / `medium` / `low`
- m4a/mp3 등도 librosa가 자동으로 읽음
- 출력 파일명: `{원본명}_snore_{번호}_{시작}s-{끝}s.wav`

## 8. 실제 녹음 튜닝 가이드

합성 테스트는 통과했으나 진짜 녹음은 노이즈 성격이 다르다. 첫 배치는 반드시:

1. `--dry-run --csv`로 먼저 돌려 검출 구간을 눈으로 확인.
2. 클립 몇 개를 직접 들어본다.
3. 상황별 조정:
   - 코골이를 너무 많이 놓침 → `-s medium` 또는 `low`
   - 노이즈가 자꾸 잡힘 → `high` 유지 또는 `SNORE_BAND`, `energy_mult` 조정
   - 호흡이 느린 편 → `PERIOD_RANGE_SEC` 상한 증가
4. 본인 녹음에 맞는 임계값을 **한 번 고정**한 뒤 전체 배치를 돌린다.

> 학습데이터 생성이 목적이므로, 임계값을 고정하면 그게 곧 향후 추론 전처리와 동일해야 한다는 점을 기억할 것.
>
> ⚠️ **정정(9장 참고):** 이 문장은 A(라벨 생성)와 B(모델 입력 전처리)를 잘못 합친 것이다. 이 스크립트의 임계값은 추론 전처리와 동일시할 대상이 아니다. 원문은 설계 기록으로 남겨둔다.
